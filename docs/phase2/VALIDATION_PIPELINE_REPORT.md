## Objectif rappelé

Ce pipeline existe pour décider si le système a le droit de tourner en **démo réelle**, puis en
**capital réel**. Un rapport qui déclare `OK` sur des étapes jamais exécutées ne protège rien : il
autorise le passage à l'argent réel sur une preuve fabriquée.

### 4. Paper trading live (Deriv) — `[FAÇADE]`

L'ancienne version affirmait un consentement explicite obligatoire.

> **Point de sécurité, formulé sans compression :** le drapeau `i_understand_this_is_real_money` vaut le
> littéral `True` dans le code (`api/deps.py:43`). Il n'est dérivé d'aucune action de l'utilisateur. Le
> garde-fou décrit comme « strict » est donc toujours ouvert. S'y ajoutent : aucune authentification sur les
> routes POST ni sur le WebSocket, et `allow_origins=["*"]` combiné à `allow_credentials=True`
> (`api/main.py:16-19`). **Aucun port ne doit être exposé avant le Lot 1.**

Par ailleurs `on_trade` a pour corps `pass` (`infrastructure/live/vnpy/execution.py:69`) : aucun retour
d'exécution ne remonte au portefeuille.

### 5. Shadow trading et coût d'exécution — `[FAÇADE]`

`ShadowTradingEngine` est censé calculer le slippage empirique en comparant le prix observé à la décision et
le prix d'exécution. Or le prix d'exécution est la constante `Decimal("100.0")`. Le slippage mesuré est donc
une fonction d'une constante : un nombre stable, reproductible, et **sans rapport avec le marché**.

Aucune. La ligne *« Waiting for continuous run data via `scripts/run_live_paper_trading.py` »* supposait un
script exécutable : **il mourait à l'import**. Il n'y a jamais eu de cycle en attente — il n'y a jamais eu

## Verdict : NO-GO

**Seule ligne de la version précédente qui était exacte** — mais pour une autre raison que celle affichée.
Ce n'était pas « en attente de données de paper trading réel » : c'était l'absence de tout mécanisme capable
de produire ces données, et de tout validateur capable de les juger.

Conditions de réouverture, dans l'ordre imposé par `docs/refont/PLAN_DE_CORRECTION.md` :
Lot 0 (`pytest` et `mypy` opérationnels) → Lot 1 (`RiskEngine` non contournable) → Lot 2 (ticks et fills
réels) → Lot 4 (validateurs qui calculent ou lèvent `NotImplementedError`).

## Ce que ce rapport ne promet pas

- **Pas de rentabilité.** Il statue sur la validité d'une mesure, pas sur un P&L.
- **Pas que le verdict deviendra GO.** Une fois les validateurs réels, ils peuvent rejeter les stratégies
  actuelles aux seuils `benchmark_gate.py:14-15`. Conformément à `CLAUDE.md`, **un rejet propre et
  reproductible est un progrès.**
- **Pas de génération automatique.** Ce fichier est écrit à la main et le dit. Il ne reprendra le titre de
  rapport généré que le jour où un générateur existera et laissera une trace `git_version` + `data_hash`.
